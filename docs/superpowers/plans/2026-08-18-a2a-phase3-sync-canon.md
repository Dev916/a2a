# A2A Phase 3: Sync Tooling + Context Canon — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the fleet a shared capability layer: `a2a sync skills` mirrors curated Claude skills into the Codex home under a manifest that can only ever touch what it created; `a2a sync mcp` translates Claude MCP servers into `[mcp_servers.*]` through a secret policy that refuses to write a literal credential into a git-published file; `doctor` grows three checks that keep all of it honest between runs. Nothing in this phase spawns a worker or touches the broker's data path.

**Architecture:** One new module tree, `src/sync/`, containing a **planner** and an **applier** that are separated on purpose: `plan()` is a pure-ish function of (source tree, dest tree, manifest, config) → `Plan`, and `apply()` is the only thing that writes. `--dry-run` runs the planner and prints, which is what makes "dry-run is side-effect-free" a structural fact rather than a discipline. `sync-manifest.json` at `$A2A_HOME` is the ownership ledger: an entry a2a did not create is never updated and never removed, and an entry it did create whose destination changed underneath it is refused rather than clobbered. Skills land flat in `$CODEX_HOME/skills/<name>/`, contained by a managed `.gitignore` block in the `codex-skills` submodule; MCP servers land in `$CODEX_HOME/config.toml` via `toml_edit`, which preserves the human's comments and formatting.

**Tech Stack:** Adds `toml_edit 0.25` (comment-preserving TOML mutation — `toml` 1.1.4 does NOT re-export it; see Ground truth). Everything else is Phase 1+2's stack: `serde_json`, `sha2` (via `brief::sha256_hex`'s crate), `chrono`, `regex` (via `redact`), `git` invoked as an argv array.

**Spec:** `docs/superpowers/specs/2026-08-14-a2a-claude-codex-design.md` (v2), §6.1 `sync skills`, §6.2 `sync mcp`, §6.3 context canon, §4.1 CLI surface, §5 secret policy, §8.8 sync test tier, §9 Phase 3 scope.

**Compatible with:** devloop skill v0.1+

## Global Constraints (Phase 1's and Phase 2's all still bind)

- **The CLI stays synchronous.** `sync` adds **no** async code and **no** tokio usage. The only async in the binary remains `a2a broker run` plus `adapter::handshake_probe`'s sanctioned current-thread runtime.
- **Zero-compiler-warning gate.** `cargo build`, `cargo test` and `cargo clippy` (if run) must be warning-free at every commit. A new `pub` item with no doc comment on an exported module is a review failure, not a warning — match the density and the *why*-first voice of `src/redact.rs` and `src/commands/doctor.rs`.
- **Tests never touch the real `~/.a2a`, `~/.codex`, `~/.claude.json`, `~/.claude-revenium` or `~/.claude/skills`.** Every test uses a temp `A2A_HOME`, a temp `CODEX_HOME` and fixture sources under `tests/fixtures/sync/`. The **only** real-machine touches in this entire plan are the explicitly gated read-only probes in Task 9.
- **That hermeticity is structural, not disciplinary.** Two mechanisms, both ACs (Task 1 for the guard, Task 3 for the helper), because `common::a2a()` sets neither `CODEX_HOME` nor any Claude pointer and a forgotten env var would otherwise write into the developer's real `~/.codex` submodule:
  1. **`common::sync_a2a(home, codex_home, claude_dir, allowed_root) -> Command`** — `common::a2a()` plus `CODEX_HOME`, `A2A_SYNC_CLAUDE_CONFIG_DIR`, `A2A_CODEX_BIN=tests/fixtures/sync/stub-codex-mcp` and `A2A_SYNC_ALLOW_REAL_HOME` unset. **Every** sync test — including Task 7's doctor cases, which shell out to `a2a sync mcp --migrate-untrack` — goes through it. A sync test that builds its `Command` any other way is a review failure.
  2. **A runtime guard in `sync_cmd`**: after resolution, if the resolved codex home or the resolved Claude config dir is the real `$HOME` or lies under it, and `A2A_SYNC_ALLOW_REAL_HOME=1` is not set, the run refuses with `AppError { code: "SYNC_REFUSES_REAL_HOME", exit: 9 }` naming both resolved paths. Task 9's gated live tests are the one caller that sets the opt-in. A forgotten env var is then a red test with a legible reason, never a write into `~/.codex`.
- **Git fixtures are hermetic.** Every fixture repo is created with `git init -q -b main` and every git invocation in a test sets `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` to a nonexistent path inside the tempdir and passes `-c user.email=a2a@test -c user.name=a2a -c commit.gpgsign=false`, so the developer's real gitconfig (hooks, signing, templates) can never reach a test.
- **`tests/common::a2a()` is unchanged** and still sets `A2A_BROKER_DISABLE=1` + `A2A_OWNER=test-owner`; sync tests reach it through `common::sync_a2a`, which only *adds* env vars. Sync opens no socket. Any test that starts a broker (**only Task 5's broker-staleness case**) starts it explicitly and tears it down through `common::BrokerGuard`.
- **Exit codes are unchanged.** Sync uses **9 (`Precondition`)** for static preconditions only, and **0** for every completed run — including runs that skipped, refused or removed things. Rationale, pinned so nobody "improves" it: a fleet-wide `sync` that exited nonzero because one destination drifted would be re-run with a bypass by every caller, which is precisely the clobber the manifest exists to prevent. The verdict travels in `data.counts`, not in the exit code. **Sync never returns 7** — it has no broker dependency.
- **Manifest-only mutation.** Nothing outside `sync-manifest.json`'s entry set is ever written, overwritten or deleted by `sync`, in any mode, ever. The one exception is the managed `.gitignore` block, which is written **before** any content and is itself delimited and idempotent.
- **Secrets never pass through agent context.** `--dry-run` and `--json` output is redacted **unconditionally** — every value that came from a source config is printed as `[REDACTED:<len>]` regardless of classification, so a misclassification cannot leak. Error and warning text names **keys, header names, env var names and line numbers**, never values. `src/redact.rs` is extended, not duplicated: sync's key-name patterns live beside the existing value shapes.
- **`git` is invoked as an argv array**, never a shell string, and only inside a directory that has already been canonicalized and confirmed to be a git work tree.
- **The plan file itself is never committed by a task executor.** Commit only the code, tests, fixtures and docs a task names.
- **Commit messages carry no co-author or generated-by lines.**
- **Deliberate deviations from the spec, recorded up front:** (1) spec §8.8's `--strict-config` post-write check is replaced by `codex mcp list --json` (§Ground truth — `--strict-config` is nondeterministic on 0.140.0); (2) spec §6.2 says Codex "cannot express arbitrary headers" — it can (`http_headers`/`env_http_headers`), so the ghl case becomes an *opt-in* rather than a permanent impossibility, with SKIP remaining the default (Task 4); (3) spec §6.3's generated global `~/.codex/AGENTS.md` is **deferred to Phase 4**, which owns `skills/**` and the worker-protocol generator — Phase 3 ships only the `context_canon` doctor check; (4) the Context7 key rotation named in spec §9 is a human action, not a task here; (5) `doctor` gains its first **security-class `fail`** (`codex_config_secrets`), which widens the module's "only a spawn-blocker may fail" rule — Task 7 amends the module doc rather than letting the code silently contradict it.

### Task 1: `sync-manifest.json` + the `[sync]` config section

**Acceptance Criteria:**

- `src/sync/manifest.rs` defines `MANIFEST_FILE = "sync-manifest.json"` (at `$A2A_HOME`, mode **0600**, written through `store::write_atomic`) and `SCHEMA_VERSION: u32 = 1`.
- One entry carries **exactly** these fields, in this JSON spelling: `source_path`, `dest_path`, `source_hash`, `dest_hash`, `synced_at` (RFC3339 UTC), `tool_version` (`env!("CARGO_PKG_VERSION")`), `kind` (`"skill"` | `"mcp"`), `account`. A unit test round-trips one entry and asserts the exact key set — a field added later without a schema bump is a test failure.
- **What `source_hash`/`dest_hash` mean depends on `kind`, pinned here because `hash_path` is not applicable to both:**
  - `kind == "skill"` → both are `hash_path(...)` over the skill directory (below).
  - `kind == "mcp"` → `dest_hash` is `mcp::canonical_table_hash` of that one `[mcp_servers.<name>]` table (Task 5), and `source_hash` is `sha256` over the **canonical JSON projection of that single server object** — the same normalization (keys sorted, values as strings, no whitespace) applied to the source. Hashing the whole 211 KB `.claude.json` is explicitly forbidden: it would give every mcp entry the same hash and make any unrelated edit mark every managed server changed, which would silently break Task 5's `unchanged` disposition and Task 8's deletion-propagation assertions. A unit test asserts two different servers in the same source file get different `source_hash`es, and that editing an unrelated server leaves a given entry's `source_hash` untouched.
- Entry key is `"<kind>:<account>:<name>"` (e.g. `skill:default:techniques`, `mcp:claude-revenium:linear`). `Manifest::key(kind, account, name)` is the only place that spelling exists, and `Manifest::owner_account(kind, name) -> Option<&str>` — implemented right beside `key`, so the spelling still exists once — is the only way to recover which account owns a name. Task 8's contended-server detail depends on it; nothing else parses a key.
- `Manifest::load(home)`: a missing file yields an **empty manifest** (not an error — a machine that has never synced is a normal machine); an unparseable file yields `AppError { code: "SYNC_MANIFEST_CORRUPT", exit: 9 }` naming the path and the parse error, with remedy `move sync-manifest.json aside and re-run the sync — a2a will only re-adopt what it can prove it wrote`. A manifest whose `schema_version` is not 1 is the same error.
- `hash_path` covers **content and relative layout, not metadata**: for a file, `sha256(bytes)`; for a directory, `sha256` over its entries sorted by relative path, each contributed as `<relpath>\0<len>\0<bytes>`; symlinks are followed; every name in `IGNORED_ENTRIES` (`.git`, `.DS_Store`, `__pycache__`, `node_modules`) is excluded at every level. Mode and mtime are **not** hashed, so a fresh copy has `source_hash == dest_hash` — pinned by a unit test that copies a fixture dir and compares.
  - **Pinned: `hash_path` feeds `sha2::Sha256` raw bytes directly and does NOT use `brief::sha256_hex`.** That helper takes `&str` (`Sha256::digest(text.as_bytes())`, `src/brief.rs:149`) and cannot hash non-UTF-8 content, and skill trees legitimately carry binaries (helper scripts, images, the `__pycache__` the fixtures mirror even though it is excluded). `tests/fixtures/sync/skills/` carries a file with deliberately non-UTF-8 bytes inside a synced skill, and a unit test hashes it — so the constraint is enforced by the suite rather than by a comment.

### Task 2: Skill classification + the read-only planner

**Acceptance Criteria:**

- `src/sync/skills.rs` pins the deny-by-default seed list **verbatim, sorted**, as `SEED_SIDE_EFFECTING: [&str; 15]`: `autologin, buildkite, cadmv-db-refresh, cadmv-grant-access, devtime, dmv-keys, docusign, meetnotes, notion-cli, pr, revenium-enterprise-deploy, slack-cli, slack-login, slack-send, x-cli`.
- `SIDE_EFFECT_VOCABULARY: [&str; 7] = ["credential", "send", "post", "deploy", "password", "token", "aws"]`, matched **case-insensitively against the skill's YAML front matter only** (the text between the first two `---` lines of `SKILL.md`), plus the directory name. Body text is deliberately **not** scanned — a doc that mentions "deploy" in an example is not a side-effecting skill, and a heuristic that flags everything is a heuristic nobody reads. A unit test asserts that a fixture whose *body* contains all seven words and whose front matter contains none classifies read-only, and that one word in the front matter flips it.
  - **The match is on ASCII-alphanumeric word boundaries, not substrings** — pinned because the two readings genuinely differ (`send` inside "sender", `token` inside "tokenizer", `post` inside "postgres", `aws` inside "laws"), and both this task's "one word in the front matter flips it" AC and Task 9's live pin that `techniques`/`technique-research` are read-only silently depend on the answer. A hit requires the character before and after the word to be absent or non-alphanumeric (`-`, `_`, `/`, space, punctuation all count as boundaries, so `slack-send` and `aws_profile` still fire). A unit test feeds a front matter containing `postgres`, `sender` and `tokenizer` and asserts **read-only**; a second feeds `slack-send` and asserts side-effecting.
- Classification order is pinned and total: **not-a-skill → collision → side-effecting → drift → unchanged → synced**.
  - **not-a-skill** (`SkippedNotASkill`): the source entry is not a directory (`README.md`), or the directory has no `SKILL.md`.
  - **collision** (`SkippedCollision`): the destination `<CODEX_HOME>/skills/<name>` exists and the manifest does **not** own it — curated ports, hand-made dirs and anything a `codex externalAgentConfig import` left behind all land here. Detail: `curated or foreign destination wins; a2a only ever updates what it created`.
  - **side-effecting** (`SkippedSideEffecting`): name ∈ `SEED_SIDE_EFFECTING`, or the front-matter heuristic fires — **unless** the name is in `[sync] allow_skills`. Detail names the reason (`seed list` or `front matter matched \`token\``), never quotes credentials.
  - **drift** (`RefusedDestDrift`): the manifest owns the destination but `hash_path(dest) != entry.dest_hash`. Refuse; never clobber. Detail: `destination was edited after the last sync; a2a will not overwrite it`.
  - **unchanged**: manifest-owned, dest hash matches the manifest, and `hash_path(source) == entry.source_hash`.
  - **synced**: everything else — a new managed skill or a source that moved on.
  - **removed** (`Removed`): the manifest owns an entry whose **source no longer exists**; the managed destination is removed on this run. If that destination has drifted, the entry becomes `RefusedDestDrift` instead and stays on disk — a user's edits are never deleted on the strength of a deletion elsewhere.
- Symlinked sources are **followed and their contents copied** (planned as ordinary directories, with `source_path` recorded as the symlink path as given, not its target — the manifest's job is to say what a2a was pointed at).
- `plan()` is **pure with respect to the filesystem**: it reads, it never writes, and it never shells out. A unit test runs it twice over a fixture tree and asserts the two `Plan`s are equal — via the `PartialEq` derived in Task 1's Interfaces, `assert_eq!(first, second)`, **not** a `Debug`-string or partial-JSON comparison — plus an unchanged tree (before/after `hash_path` of the fixture root).
- The managed-ignore helpers are here and are pure string functions: `BEGIN_MARK = "# BEGIN a2a-sync"`, `END_MARK = "# END a2a-sync"`; `managed_block(dirs)` renders the marker pair with one `/<dir>/` line per managed dir, sorted; `block_covers(gitignore, dirs)` is true only when a well-formed block exists **and** contains a line for every dir; `rewrite_block(gitignore, dirs)` replaces an existing block in place (preserving everything outside it byte-for-byte) or appends one separated by a single blank line. Unit tests cover: absent block, present-and-complete, present-but-missing-one-dir, two `BEGIN` markers (malformed → `block_covers` false and `rewrite_block` collapses to one), and idempotence (`rewrite_block(rewrite_block(x)) == rewrite_block(x)`).
- **`managed_dirs` is a property of the destination tree, not of one account** — it takes **no `account` parameter**. Skills land flat in the single shared `<CODEX_HOME>/skills`, and `account_label` is pinned to `"default"` for skills (Task 1), so an account filter here would be either dead or actively harmful: a second account's `sync skills` would rewrite the one managed block without the first account's directories, uncovering them, turning the fixture repo dirty and silently breaking Task 3's containment invariant with no test to catch it. The signature is `managed_dirs(plan, manifest) -> Vec<String>` = every destination dir **every** skill entry in the manifest tracks (regardless of account) ∪ every dir this plan would create, sorted and deduped. A unit test builds a manifest holding entries under two different account labels and asserts both appear.

Warn rather than fail: a corrupt ledger does not stop a spawn.
